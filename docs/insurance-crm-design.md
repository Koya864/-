# 保険営業向け顧客管理ツール 企画・設計ドキュメント

## コンセプト

**「顧客リストを管理するツール」ではなく「関係性を育てるツール」**

一般的なCRMは「顧客情報のデータベース」で終わる。このツールは、保険営業の本質が
「契約時点ではなく、契約後の長い付き合いの中で信頼を積み上げること」にある点に着目し、
**関係の鮮度・深さを可視化し、次の一手を営業マンに先回りで提案する**ことを中核に据える。

---

## 1. 基本機能（土台）

### 顧客プロファイル
- 基本情報：氏名、連絡先、職業、家族構成（配偶者・子どもの名前と生年月日）
- 契約情報：商品名、契約日、更新日、保険料、受取人
- パーソナル情報：趣味、好きな話題、健康の話、NGトピック
- タグ管理（例：「ゴルフ好き」「子ども2人」「転職検討中」）

### リマインダーエンジン
- 契約記念日 / 契約更新日（90日前・30日前・7日前の段階通知）
- 顧客・家族の誕生日
- 初回面談記念日（「お付き合いいただいて◯年」の演出に使える）
- 「前回接触から◯日経過」アラート

### 面談メモ
- 面談・電話・偶然会った時のメモをタイムライン形式で記録
- 日付、場所、話題、次のアクションを紐付け

---

## 2. 画期的な仕組み（差別化ポイント）

### ★ A. AI面談ブリーフィング「会う前の3分予習」

**このツールの目玉機能。**

顧客に会う前にワンタップで、AIがその顧客の全履歴から
**A4半分のブリーフィングシート**を自動生成する。

> - 前回会ったのは3ヶ月前。娘さんの受験の話をした → 「結果どうでしたか？」が最初の一言
> - 契約更新まであと4ヶ月。前回「保険料を少し抑えたい」と発言あり
> - 誕生日が来月。趣味は釣り
> - 提案の温度感：まだ売り込みは早い。今回は近況ヒアリングに徹する回

営業マンの「あの人、前に何の話したっけ…」を完全に解消する。
**記憶力の差を武器の差にしない**ことで、コミュニケーションの質が底上げされる。

### ★ B. 音声・雑メモ → AI自動構造化

面談後、車の中で音声またはざっくりテキストで放り込むだけ：

> 「田中さん、息子さんが来年就職らしい。腰痛めてゴルフ休んでる。
> 更新の話したら医療特約気にしてた」

AIがこれを解析して：
- 家族情報を更新（息子：2027年就職予定）
- 健康メモに「腰痛・ゴルフ休止中」を追加
- 商談メモに「医療特約に関心あり」を記録し、更新商談の論点として登録
- 次アクション候補「就職祝いのタイミングで連絡」を提案

**入力コストほぼゼロで、データベースが勝手に育つ。**
CRMが失敗する最大の理由は「入力が面倒で続かない」こと。ここを潰す。

### ★ C. ライフイベント予測タイムライン

家族構成と年齢から、**将来のライフイベントを自動で先回り予測**して
カレンダーに載せる。保険営業の商機は「更新日」ではなく「人生の節目」にある。

| 予測イベント | 提案チャンス |
|---|---|
| 子どもの小学校入学（年齢から自動算出） | 学資保険・見直し |
| 子どもの18歳・22歳（進学・就職） | 保障額の見直し |
| 本人の40歳・50歳・60歳の節目 | 医療・がん保険、退職金準備 |
| 住宅ローン完済推定年 | 死亡保障の減額提案（信頼獲得） |
| 定年推定年の5年前 | 年金・介護の相談 |

「売れるタイミングの提案」だけでなく、**保障を減らす提案**（顧客の得になる提案）も
出すことで、信頼ベースの営業を支援する。

### ★ D. 関係温度スコア（リレーションシップ・ヘルス）

顧客ごとに「関係の温度」を1つのスコアで可視化：

- 最終接触からの経過日数（減点）
- 接触頻度・双方向性（先方から連絡が来たか）
- メモの内容（個人的な話題が出ているか＝関係の深さ）
- 記念日フォローの実施率

ダッシュボードは「顧客一覧」ではなく **「今週、温度が下がっている人 TOP5」** を表示。
やることが毎朝明確になる。全顧客を平等に見るのではなく、
**冷めかけている関係に先に水をやる**という発想。

### ★ E. 「ご縁ノート」— 顧客に還元される記録

たまり続けたメモを営業マンだけの資産にせず、節目で顧客に還元する仕組み。

- 契約10年目に「この10年の歩み」を自動生成（初めて会った日、お子さんの成長、
  保障を見直した経緯…）を1枚のレターにして手渡せる
- 「あなたのことをずっと見てきました」が形になる。**他社に絶対真似できない乗り換え防止策。**

## 3. 技術構成（Webアプリ / 個人〜小規模チーム前提）

| レイヤ | 技術 | 理由 |
|---|---|---|
| フロント | Next.js (App Router) + TypeScript + Tailwind | 開発速度・PWA化でスマホ対応 |
| バックエンド/DB | Supabase (PostgreSQL + Auth + RLS) | 認証・行レベルセキュリティ込みで最速 |
| AI | Claude API | メモ構造化・ブリーフィング生成・音声書き起こし後処理 |
| 通知 | LINE Messaging API / メール / Web Push | 営業マンはLINE通知が一番見る |
| ホスティング | Vercel | Next.jsと相性◎、無料枠で開始可 |

### セキュリティ（保険業界では必須要件）
- 健康情報・家族情報は**機微情報**。保存時暗号化＋アクセスログ必須
- Supabase RLSで営業マン本人以外はデータに触れない設計
- AI処理はデータを学習に使わないAPI（Claude API等）を明記して利用

### データモデル（概要）
```
customers（顧客）
├─ family_members（家族：名前・続柄・生年月日）
├─ contracts（契約：商品・契約日・更新日・保険料）
├─ interactions（接触履歴：日時・種別・生メモ・AI構造化結果）
├─ life_events（予測/実績ライフイベント）
├─ reminders（記念日・更新・フォロー通知）
└─ relationship_scores（関係温度の時系列）
```

## 4. 開発ロードマップ

### Phase 1: MVP（〜1.5ヶ月）
顧客管理 + 契約/記念日リマインダー + 面談メモ（タイムライン）
→ まず相談元の営業マン本人に毎日使ってもらう

### Phase 2: AI導入（〜3ヶ月）
音声/雑メモのAI構造化（B）+ 面談前ブリーフィング（A）
→ ここで「普通のCRM」を超える

### Phase 3: 先回りエンジン（〜5ヶ月）
ライフイベント予測（C）+ 関係温度スコア（D）

### Phase 4: 差別化の完成
ご縁ノート（E）+ チーム展開・他の営業マンへの横展開（SaaS化の検討）

## 5. 将来の広がり

- 保険以外の「長期リレーション型営業」（不動産、車ディーラー、税理士、美容室）に
  ほぼそのまま横展開できる設計にしておく
- 「LTV（生涯顧客価値）を伸ばすリレーションシップCRM」という市場ポジション
