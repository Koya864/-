# 01. サイト構造・SEO/LLMO・URL設計

対応事項: **1. SEO・LLMOに最適なサイト構造** / **10. SEOを意識したURL設計・カテゴリ設計**

## 基本方針

- SEOの主戦場は**物件詳細ページ**と**カテゴリページ**。TOPは指名検索の受け皿。
- 認定制（85点以上のみ掲載）は掲載数が少ないため、**「量で戦わず、1ページあたりの情報品質と独自性で戦う」**。
  Life Shift独自の認定コメント・評価がそのまま「他サイトにない独自コンテンツ」となり、SEO・LLMO両方の資産になる。
- 物件は成約・掲載終了で消える。**終了ページを404にせず、資産として残す設計**が長期SEOの鍵（後述）。

## URL設計

```
/                                        TOP
/aichi/                                  都道府県トップ（エリアハブ）
/aichi/nagoya/                           市区町村カテゴリ
/aichi/nagoya/mansion/                   市区町村 × 物件種別
/aichi/nagoya/mansion/used/              市区町村 × 種別 × 中古/新築
/station/meieki/                         駅カテゴリ（駅名スラッグ）
/station/meieki/mansion/
/features/high-asset-value/              特徴カテゴリ（資産価値が高い 等）
/features/easy-to-sell/
/properties/{property-slug}/             物件詳細（例: aichi-okazaki-xxx-1203）
/guide/…                                 コンテンツ（住宅購入ガイド等）
/certification/                          Life Shift認定とは（ブランドページ）
```

### 設計ルール

1. **階層は「都道府県 > 市区町村 > 種別 > 条件」**。将来の全国展開時もURL体系を変えずに増やせる。
2. 物件スラッグは `{都道府県}-{市区町村}-{物件名ローマ字}-{部屋番号等}` を基本とし、
   **公開後は変更しない**（変更時は301リダイレクト必須）。IDのみのURL（`/properties/12345`）は避ける。
3. 駅・特徴は市区町村階層と直交する軸なので `/station/` `/features/` として独立させ、
   組み合わせページ（駅×種別など）は**掲載物件が1件以上あるものだけ生成**する。
   0件ページの量産はソフト404・低品質評価の原因になるため、生成条件をCMS側で制御する。
4. 正規化: 絞り込みの組み合わせ爆発を防ぐため、
   **インデックスさせる軸は「エリア・駅・種別・特徴・価格帯」の5軸まで**。
   それ以外の絞り込み（例: 築年数×階数）はクエリパラメータ + `noindex` で処理。

## レンダリング戦略（Next.js）

| ページ | 方式 | 更新 |
|-------|------|------|
| TOP | ISR（revalidate: 1h） | 人気・新着の入れ替え |
| カテゴリページ | ISR（revalidate: 1h）+ 掲載0件なら生成しない | 物件の増減で自動再生成（on-demand revalidation） |
| 物件詳細 | ISR + 掲載/価格変更時にon-demand revalidate | 常に最新価格を保証（おとり広告対策としても重要） |
| 会員限定分析 | SSR（認証必須・noindex） | — |

## 物件詳細ページの構造（SEO・LLMO共通のコア）

各物件ページに以下を**構造化して**配置する。これが企画書の「LLMO対策」の実装形。

```html
<article>
  <h1>{物件名}｜{市区町村}の{種別}【Life Shift認定 ランクS】</h1>

  <section id="summary">        価格・所在地・基本スペック（表形式）
  <section id="certification">  Life Shift認定ランク + 総合評価（公開範囲のみ）
  <section id="recommendation"> おすすめ理由（見出し + 箇条書き3〜5点）
  <section id="suitable-for">   向いている人（箇条書き）
  <section id="cautions">       注意点（箇条書き。正直に書く＝信頼性・E-E-A-T）
  <section id="ls-comment">     Life Shift担当者コメント（署名・宅建士名入り）
  <section id="area">           周辺環境・駅距離・学区
  <section id="faq">            この物件に関するFAQ（3〜5問）
</article>
```

### LLMO（AIに引用されやすくする）実装ポイント

1. **JSON-LD構造化データ**を全物件ページに埋め込む:
   - `RealEstateListing` + `Offer`（価格・通貨・所在地）
   - `FAQPage`（FAQセクション）
   - `BreadcrumbList`
   - `Organization`（Life Shift。認定の発行主体として明示）
2. **「質問→簡潔な答え」の形**でFAQ・注意点を書く。AI検索は自己完結した段落を引用する。
3. **一次情報の明示**: 「Life Shift認定基準（85点以上）を満たした物件」と定型文で明記し、
   認定制度の説明ページ `/certification/` へ内部リンク。AIが「Life Shift認定とは何か」を
   説明できる状態を作ると、ブランド名ごと引用されやすくなる。
4. `llms.txt` をルートに設置し、サイト構造・認定制度の説明を記載する（コストゼロの保険）。
5. 評価の**採点ロジック・計算式は絶対にページに書かない**（ブラックボックス方針）。
   公開するのは「ランク・総合評価・コメント」のみ。構造化データにもスコア内訳は含めない。

## 掲載終了物件の扱い（長期SEO資産化）

- 成約・掲載終了後も**ページは残し、「成約済み」表示に切り替える**。
  価格・詳細は非表示化し、「類似の認定物件」への導線を置く。
- ただし宅建業法上、**取引できない物件を取引可能に見せることは「おとり広告」**になるため、
  成約済みであることをファーストビューで明示し、エントリーボタンは撤去する（詳細: 10-legal.md）。
- 一定期間（例: 6ヶ月）経過後は `/sold/` アーカイブへ301 or 類似カテゴリへ301。

## コンテンツSEO（カテゴリページを空にしないために）

Phase1は物件数が少ないため、カテゴリページには物件リストだけでなく:

- そのエリアの相場観・資産価値に関するLife Shiftの解説（500〜1000字）
- 「このエリアで認定物件が少ない理由」等の正直な解説（差別化・E-E-A-T）
- `/guide/` 配下の購入ガイド記事からの内部リンク

を配置し、**物件0〜2件でも独自価値のあるページ**にする。

## 計測

- Google Search Console + GA4 は初日から導入。
- 物件ページごとの「表示回数→クリック→お気に入り→エントリー」ファネルをGA4イベントで設計
  （イベント名: `view_property` / `add_favorite` / `start_entry` / `submit_entry`）。
