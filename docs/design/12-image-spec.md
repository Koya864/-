# 12. 画像仕様（推奨比率・サイズ）

対応: プロトタイプの各画像スロットに入れる写真の推奨比率・解像度・容量の基準。
管理会社・運営が写真を差し替える際、これに沿えばレイアウト崩れ・画質不足が起きない。

## まず押さえる3原則

1. **必ず「表示比率」に合わせて用意する。** 表示は `object-fit: cover`（枠を写真で埋める）方式のため、
   比率が違うと**上下または左右が自動でトリミング**される。被写体は中央寄せ・端に余白を持たせる。
2. **表示サイズの「2倍(2x)」で用意する。** 高解像度ディスプレイ（スマホ・Retina）で滲まないため。
   例: 表示幅600pxの枠なら、実データは横1200pxで用意。
3. **形式は WebP を基本、JPEG可。** 写真はPNG不可（重すぎる）。色空間は sRGB。
   実装（Next.js の画像最適化）が閲覧環境に応じてWebP/AVIFへ自動変換・リサイズするため、
   **アップロード時は下表の「推奨アップロードサイズ」で高品質な元画像**を入れればよい。

## 物件写真の撮影ガイド（管理会社向け・任意）

掲載品質を揃えるための推奨。強制ではないが、認定制のブランド維持に効く。

- **明るい時間帯・自然光**で撮影（暗い写真はAI評価でも減点対象になりうる）。
- **横位置（ランドマーク）で撮る** — 縦写真はカード（4:3横長）で大きくトリミングされる。
- 1枚目は「広く明るいリビング」または「外観正面」。生活感（私物）は片付ける。
- 極端な広角の歪み・過度なHDR加工は避ける（優良誤認・現地との乖離の観点でも）。
- 最低でも**長辺1600px以上**。スマホ標準画質で十分満たせる。

## 実装メモ

- Next.js は `next/image` を使用。`sizes` 属性で表示幅を指定し、実配信は自動で最適サイズ・WebP/AVIF化。
  → アップロードは高解像度原本を1つ入れれば、各画面用のサイズは自動生成される。
- ヒーロー画像のみ LCP（最大表示要素）になるため `priority` 指定＋容量最優先で軽量化。
- 保存は Supabase Storage（またはCloudflare Images）。オリジナルを保持し、配信はCDN経由。
- **本プロトタイプの写真は参考画像から採寸した仮のイメージで、解像度が低く粗い**。
  本番は上表の推奨サイズで差し替えれば鮮明になる（現状の粗さは元素材の解像度が原因で、レイアウトの問題ではない）。
