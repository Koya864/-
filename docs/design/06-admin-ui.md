# 06. 管理画面UI

対応事項: **3. 管理画面UI**

## 全体構成

管理画面は**2系統**に分ける（権限も画面も混ぜない。13参照）。

1. **運営管理画面**（Life Shift社内） — `/admin`
2. **管理会社ポータル**（掲載パートナー） — `/partner`

どちらもモバイル対応は「閲覧・承認・ステータス確認」ができるレベルでよい
（本格的な入力作業はPC前提。営業担当が外出先で審査承認・エントリー確認できることが重要）。

## 6-1. 運営管理画面（/admin）

### 情報設計の中心 = 「審査キュー」と「商談パイプライン」

日々の業務は「審査する」「エントリーをさばく」の2つ。ダッシュボードはこの2つのTo-Doを最上部に置く。

```
┌──────────────────────────────────────────────┐
│ ダッシュボード                                  │
│ ┌──────────────┐ ┌──────────────────────┐    │
│ │ 審査待ち  3件 │ │ エントリー期間終了 2件 │ ← 今日やること
│ └──────────────┘ └──────────────────────┘    │
│ 掲載中 24 / 保留 6 / 今週の新規エントリー 18   │
└──────────────────────────────────────────────┘

サイドナビ:
  📋 審査キュー        ← AI評価済み・人間の判断待ち
  🏠 物件・掲載管理
  🎯 エントリー管理     ← 物件ごとのエントリー一覧・優先権付与
  💬 商談パイプライン   ← 優先権付与後の進捗（案内済/商談中/契約/繰上げ）
  👥 会員管理
  🏢 管理会社管理      ← アカウント審査・免許確認
  📊 SEOカテゴリ管理   ← カテゴリ文言・生成状況
  ⚙️ 設定（評価エンジンver・スタッフ・監査ログ）
```

### 審査画面（最重要画面）

1画面で判断が完結するレイアウトにする:

```
┌─────────────────────┬───────────────────────┐
│ 物件情報プレビュー     │ AI評価パネル            │
│ （公開ページと同じ見た目│  総合: 87.5 / ランクA   │
│  でプレビュー表示）    │  内訳: レーダーチャート   │
│                      │  AIサマリ・懸念点        │
│  写真ギャラリー        │  類似成約事例           │
│                      ├───────────────────────┤
│  抽出元資料（概要書）   │ 判断                    │
│  と抽出結果の対比表示   │ [掲載承認] [保留] [却下] │
│  ※要確認項目は赤表示   │ 理由（必須・監査証跡）    │
└─────────────────────┴───────────────────────┘
```

- **AI評価はあくまで補助**という企画方針を画面でも徹底:
  承認ボタンは判断理由の記入必須。ワンクリック一括承認は作らない。
- 保留時は改善提案（AI下書き）の編集画面に遷移 → 管理会社へ送信。

### エントリー管理・優先権付与画面

```
物件: ○○マンション 302号 [エントリー期間終了]
提案順位（ルール自動算出）:
  1. 山田様  現金          6/28 14:02  [事前審査: -]
  2. 佐藤様  ローン(審査済) 6/25 09:11
  3. 鈴木様  ローン(未)     6/24 18:30
[この順位で優先権を確定する]  [順位を手動調整（理由必須）]
確定後: 第1順位へ案内テンプレ送信 → 期限タイマー表示 → 期限切れ/辞退で[繰り上げ]ボタン
```

## 6-2. 管理会社ポータル（/partner）

シンプルさ最優先。メニューは3つだけ。

```
🏠 物件一覧      ステータスバッジ（審査中/掲載中/保留/成約）+ エントリー数
＋ 新規掲載      概要書D&D → AI解析 → 確認 → 提出（05参照）
🏢 会社情報      担当者・ドメイン・プラン
```

- 物件一覧の各行に「販売継続確認」の応答ボタンを出す（おとり広告対策の運用を軽くする）。
- 保留物件は改善提案カードを表示し、「修正して再提出」を1ボタンで。

## 実装方針

- 独自実装（Next.js + shadcn/ui の管理画面テンプレ）を推奨。
  Retool等のローコードは初速は出るが、審査画面のような作り込み・RLS連携で行き詰まりやすい。
- 全ての状態変更（承認・保留・優先権確定・価格変更）は `audit_logs` テーブルへ自動記録
  （actor / action / target / before / after / reason）。
