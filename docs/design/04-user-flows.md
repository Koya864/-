# 04. 会員登録・購入エントリー・優先購入権ロジック

対応事項: **4. 会員登録フロー** / **5. 購入エントリーフロー** / **6. 優先購入権のロジック設計**

## 4-1. 会員登録フロー

### 方針

- 閲覧のハードルは下げ、**行動（お気に入り・エントリー）の直前で登録させる**。
  高級感のあるブランドは「登録の壁」を最初に出さない。
- 段階的プロフィール収集: 登録時は最小限、エントリー時に購入意思に関わる情報を追加取得。

### 会員ステージ設計

| ステージ | できること | 取得情報 |
|---------|-----------|---------|
| ゲスト | 物件閲覧（詳細分析以外すべて） | なし |
| 無料会員 | お気に入り / 詳細分析の閲覧 / 新着通知 | メール（or Google/LINE）+ 氏名 + パスワード |
| エントリー会員 | 購入エントリー | 電話番号（SMS認証）+ 購入予算 + 資金計画（現金/ローン・事前審査有無）+ 現住所 |

### フロー

```
物件詳細で「詳細分析を見る」or「お気に入り」タップ
  → モーダルで登録（メール or Google or LINE）      ※離脱防止: ページ遷移させない
  → メール確認リンク
  → 元のページに戻る（文脈を失わせない）

エントリーボタン → 未認証項目があれば追加入力ステップ
  → SMS認証（なりすまし・重複エントリー防止）
  → エントリー完了
```

- **LINEログインは優先度高**。ターゲット（20〜40代・日本）との相性がよく、
  エントリー後の担当者連絡チャネルとしても使える。
- SMS認証はエントリー時のみ必須とする。無料会員登録では要求しない（CVR優先）。

## 4-2. 購入エントリーフロー

### 名称

候補のうち **「優先購入エントリー」** を推奨。
「購入リクエスト」は問い合わせと区別がつかず、「購入エントリー」は"購入の申込み"と
誤認されるリスクが相対的に高い。「優先」を冠することで
**"購入権の獲得を目指す手続きであり、契約ではない"** ことが名称レベルで伝わる。

### フロー

```
物件詳細「優先購入エントリー」
  ↓
Step1 エントリー内容の確認
  ・エントリーは契約ではないことの明示（太字・最上部）
  ・エントリー期間・結果連絡日・優先権の決まり方（公開ルール）の説明
  ↓
Step2 購入計画の入力
  ・支払い方法（現金 / 住宅ローン）
  ・ローンの場合: 事前審査の有無（済みなら優先度に反映される旨を明示）
  ・入居希望時期 / 一言メッセージ（任意）
  ↓
Step3 確認 → 送信
  ↓
完了画面 + メール/LINE通知
  「エントリー期間終了後（○月○日）、担当者よりご連絡します」
```

### エントリー後の表示（企画書方針の実装）

- 物件ページには **「現在◯名が検討中」のみ**表示。順位・入札額的な数値は一切出さない。
- 本人のマイページには「エントリー中」ステータスと期間終了日のみ。**自分の順位も見せない**
  （順位を見せる＝ゲーム性・競争演出になるため）。
- 検討中人数の表示は 3名未満なら「検討中の方がいます」等の丸め表現にする
  （少人数だと個人が特定されうる・不人気に見える、の両方を回避）。

### キャンセル

- エントリー期間中はマイページからいつでも撤回可能（`withdrawn`）。
- 撤回のしやすさは法的安全性（申込みと誤認させない）とブランド信頼の両方に効く。

## 4-3. 優先購入権のロジック設計

### 設計原則

1. **ルールは事前公開・機械的に適用**する。恣意的に見える選定は
   トラブル・宅建業法上の説明義務問題・ブランド毀損に直結する。
2. ただし**「高く買う人が勝つ」構造にはしない**（オークション禁止方針）。価格は固定。
3. 順位付与時のルールと入力値は `entry_priorities.rule_snapshot` に保存し、後から説明可能にする。

### 推奨ロジック: 「成約確実性ベースの順位付け + 先着タイブレーク」

エントリー期間終了時に、以下で順位を決定する。

```
第1キー: 資金準備状況（成約確実性）
   1. 現金購入
   2. 住宅ローン事前審査 承認済み
   3. 事前審査 未実施
第2キー: エントリー日時（先着）
```

- 「早い者勝ちだけ」だと熟慮せず即エントリーする行動を誘発し、
  「抽選」だと真剣な購入者が運で落ちる。**成約確実性を第1キーにするのが売主の利益とも一致**し、
  管理会社への営業上の説明も立つ（"Life Shift経由は決済まで速い"）。
- 事前審査を優遇することは、収益モデルの「住宅ローン紹介」への自然な導線にもなる
  （エントリー前に自社経由で事前審査を案内できる）。

### 優先権の運用フロー

```
エントリー期間終了
  ↓ システムが順位を自動算出 → 運営が確認・確定（最終判断は人間）
第1順位者に「優先購入のご案内」（メール/LINE + 電話）
  ↓ 回答期限: 案内から【5営業日】（expires_atで管理）
  ├ 商談へ → 担当者相談 → 分析説明 → ローン相談 → 購入意思確認 → 契約
  ├ 辞退(passed) / 期限切れ(expired)
  │    ↓
  └ 第2順位者へ繰り上げ案内（以下同様）
エントリー者全員が辞退 → 通常問い合わせ受付に切り替え or 再エントリー期間設定
```

### エッジケースの扱い

| ケース | 扱い |
|-------|------|
| エントリー0件で期間終了 | 掲載継続 + 「問い合わせ」導線に切替。期間の再設定可 |
| エントリー期間中に売主都合で販売中止 | 全エントリー者に通知・謝罪文面テンプレを用意 |
| 優先権者との商談中の他エントリー者 | 「現在、優先のお客様と商談中です」表示。繰り上げの可能性がある旨を通知 |
| 同一人物の複数アカウント | SMS認証（電話番号一意）で抑止 |
| 商談が長期化 | 商談開始から【14日】で意思確認、最大【30日】で次順位へ（社内SLA。規約に明記） |

### 法的な位置づけ（詳細は 10-legal.md）

- エントリー・優先権付与は**売買契約の申込み・承諾ではない**ことを規約と画面の両方で明示する。
- 優先権は「一定期間、優先的に商談できる地位」であり、購入を義務づけない・価格交渉を伴わない。
- 順位決定ルールは利用規約に明記し、変更時は掲載中物件には旧ルールを適用する。
