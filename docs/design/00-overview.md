## 推奨技術スタック（結論）

| レイヤ | 推奨 | 理由 |
|-------|------|------|
| フロントエンド | **Next.js 15（App Router）+ TypeScript** | SSG/ISRによるSEO最適化。物件ページ・カテゴリページの大量生成に最適。構造化データ（JSON-LD）の埋め込みが容易 |
| スタイリング | Tailwind CSS + shadcn/ui | 余白主体・カードUIの高級感デザインを高速に構築。デザイントークンで統一 |
| バックエンド / DB | **PostgreSQL（Supabase推奨）** | RLS（行レベルセキュリティ）で3者権限を実装しやすい。認証・ストレージ（物件写真）・Edge Functionsが同梱でMVPに最速 |
| ORM | Prisma または Drizzle | スキーマのバージョン管理・マイグレーション |
| AI | Claude API（claude-sonnet-5 / claude-haiku-4-5） | 物件情報の構造化抽出・評価補助・おすすめコメント生成 |
| ホスティング | Vercel | ISR・画像最適化（next/image）・プレビュー環境 |
| 検索 | MVP: PostgreSQL全文検索 + インデックス / 将来: Algolia or Meilisearch | Phase1（愛知県のみ）はDB検索で十分 |
| 画像配信 | Supabase Storage + next/image（またはCloudflare Images） | 写真主体UIのため画像最適化は必須 |

## 設計上の重要な結論（サマリ）

1. **SUUMO等のURLスクレイピングは法的リスクが高く、MVPでは採用しない。**
   代替として「管理会社の自社サイトURL or 物件概要書PDF/画像のアップロード → AI構造化抽出」を推奨（詳細: 02）。
2. **SEOの主戦場である物件ページ・カテゴリページはISRで静的生成**し、
   認定済み物件のみをインデックス対象にする（詳細: 01）。
3. **優先購入権は「透明なルールに基づく順位付け + 繰り上げ制」**とし、
   オークション的演出は排除する（詳細: 04）。
4. **評価ロジックはバージョン管理された「評価エンジン」として分離**し、
   スコアは再計算可能な形で保存する（詳細: 07）。
5. **法務面は宅建業法の広告規制（おとり広告・取引態様明示）が最重要。**
   掲載前に必ず宅建士・弁護士のレビューを受けること（詳細: 10）。
