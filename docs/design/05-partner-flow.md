# 05. 管理会社向け掲載フロー

対応事項: **7. 管理会社向け掲載フロー**

## 方針

- 企画書の理想「URLを貼るだけ」は、法的制約（02参照）により
  **「概要書を投げるだけ / 自社URLを貼るだけ」**に読み替えて実現する。管理会社の実作業は2〜3分。
- 管理会社側の心理は「手間をかけたくない」+「審査に落ちたくない」。
  **審査状況の透明性**と**落ちた場合の改善提案**をフローに組み込み、掲載保留をネガティブ体験にしない。

## アカウント開設（初回のみ）

```
申込みフォーム（会社名・宅建免許番号・担当者・自社サイトURL）
  ↓
運営が審査（免許番号の実在確認・反社チェック）※取引相手の審査はブランドの生命線
  ↓
承認 → アカウント発行 → 掲載規約への同意（電子）
        規約に含める: 情報・写真の権利保証 / 掲載基準への同意 /
        成約時の報告義務 / おとり広告防止（成約時の即時連絡義務）
```

- 免許番号は国土交通省「建設業者・宅建業者等企業情報検索システム」で確認する運用をマニュアル化。
- 自社ドメインをこの時点で登録 → 方式B（URL取得）のドメイン検証に使う。

## 物件掲載フロー（2回目以降はこれだけ）

```
① 新規掲載 をクリック
② 情報を投げる（いずれか1つ。所要1〜2分）
   ┌ A. 物件概要書PDF/画像をドラッグ&ドロップ 【推奨・MVP】
   ├ B. 自社サイトの物件URLを貼る 【Phase1.5】
   └ C. フォーム手入力（AI補完付き）
③ オリジナル写真をアップロード（権利確認チェックボックス付き）
④ AIが下書きを自動生成 →「解析中」（数十秒〜数分、完了をメール通知）
⑤ 確認画面: AI抽出結果を確認・修正（要確認項目はハイライト）
   → 取引態様・告知事項など宅建業法上の必須項目は空欄だと提出不可
⑥ 提出 → ステータス「審査中」
```

## 審査〜掲載のステータス遷移（管理会社に見える形）

```
審査中 ──→ 掲載決定（85点以上 + 社内承認）──→ 掲載中 ──→ エントリー受付終了
   │                                              │
   └─→ 掲載保留                                成約/取下げ
         └ 改善提案を表示:
            ・価格調整の提案（「○○万円程度で再評価の可能性」）
            ・写真改善の提案（具体的に: 「リビングの明るい写真を追加」）
            ・リフォーム提案
         └ 修正して再提出 → 再評価
```

- **点数そのもの・採点内訳は管理会社にも開示しない**（ブラックボックス方針は対外全方位）。
  開示するのは「掲載決定 / 保留」+ 改善提案のみ。
  ※「何点足りないか」を開示すると逆算でロジックが推定されるため。
- 保留理由の改善提案はAI生成（`evaluations.improvement_suggestions`）を運営が確認してから送る。

## 掲載中の管理会社の義務・操作

| 操作 | 内容 |
|------|------|
| 価格変更 | 申請 → 運営確認 → 反映（再評価トリガ。大幅変更は再審査） |
| 成約報告 | **他ルートで成約したら即日報告**（規約義務）。放置=おとり広告リスクのため、掲載後30日ごとに「販売継続確認」を自動送信し、無応答なら掲載を自動停止 |
| 取下げ | 即時反映。エントリー者がいる場合は運営に警告表示 |
| エントリー状況閲覧 | 件数のみ（エントリー者の個人情報は運営のみ。13-権限設計参照） |

## 収益モデルとの接続

- プラン（standard / premium）は `listings.plan` で管理。
  premiumは「TOPの認定物件一覧での優先表示・写真枠追加」等。**検索順位そのものは売らない**
  （認定制の信頼性が毀損されるため。掲載順は認定ランク・新着が基本）。
- MVPでは請求は手動（請求書払い）でよい。Stripe連携はPhase2。
