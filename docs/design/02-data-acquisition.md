# 02. AIによる物件情報取得 — 法的・技術的実現性

対応事項: **2. AIによる物件情報取得方法（URL入力・スクレイピング・APIなど）**

## 結論（最重要）

> **SUUMO等の他社ポータルURLをスクレイピングする方式は、MVPでは採用しない。**
> 代替として「**管理会社が権利を持つ情報源（自社サイトURL・物件概要書・レインズ登録情報の手元データ）をアップロード → AIが構造化抽出**」方式を推奨する。
> UX上の理想（URLを貼るだけ）は、**貼るURLを"管理会社自身のページ"に限定**することでほぼ達成できる。

## 法的リスクの整理

### SUUMO等のポータルサイトをスクレイピングする場合

| 論点 | 内容 | リスク |
|------|------|--------|
| 利用規約違反 | SUUMO・HOME'S・アットホーム等は規約で自動取得（クローリング/スクレイピング）を明示的に禁止 | **高**。債務不履行・不法行為に基づく損害賠償、アクセス遮断。商用サービスの基盤には据えられない |
| 著作権（写真） | 物件写真の著作権は撮影者（管理会社 or ポータル側カメラマン）に帰属。ポータル経由で取得した写真の転載は複製権・公衆送信権侵害 | **高**。写真は特に権利関係が明確で、差止・賠償の典型例 |
| 著作権（データベース） | ポータルの物件DBは編集著作物・データベースの著作物に該当し得る | 中 |
| 不正競争防止法 | 相当の労力で収集されたデータの無断利用は「限定提供データ」侵害等の主張余地 | 中 |
| 業務妨害 | 高頻度アクセスによるサーバ負荷 | 低〜中（頻度次第） |

**「掲載依頼者（管理会社）が自ら掲載した情報だから良いのでは」という理屈は通らない**点に注意。
情報の元の権利者が管理会社でも、ポータル上の表現物（写真の加工版・原稿・ページ構造）には
ポータル側の権利・規約が及ぶ。管理会社の同意はポータルの規約違反を治癒しない。

### 推奨方式の法的位置づけ

管理会社が**自ら権利を持つ・自ら提供する**情報をAIで構造化する分には、上記リスクは発生しない。
必要なのは掲載規約での担保のみ:

- 掲載依頼時に「提供する情報・写真について正当な権利を有し、掲載を許諾する」旨を規約で確認
- 写真の撮影者・権利帰属のヒアリング項目を掲載フォームに含める

## 推奨する取得方式（優先順）

### 方式A: 物件概要書・マイソク・販売図面のアップロード → AI抽出【MVP採用】

管理会社は必ず物件概要書（PDF/画像）を持っている。これをアップロードさせ、
Claude API（vision対応モデル）で構造化抽出する。

```
アップロード(PDF/JPG/PNG)
  → Claude API（マルチモーダル）で読み取り
  → JSONスキーマに構造化（価格・所在地・面積・築年・間取り・管理費…）
  → 信頼度スコア付きで抽出（不明項目は null + 要確認フラグ）
  → 管理会社/運営が確認画面で修正・承認
```

- **法的に最も安全**（提供者自身の資料）
- 精度が高い（概要書はフォーマットが定型的）
- 写真は概要書とは別に、管理会社がオリジナル写真をアップロード

抽出スキーマ例:

```json
{
  "property_type": "used_mansion",
  "name": "○○マンション",
  "price": 32800000,
  "address": {"prefecture": "愛知県", "city": "岡崎市", "town": "…"},
  "station": [{"line": "名鉄名古屋本線", "name": "東岡崎", "walk_min": 8}],
  "floor_area_sqm": 71.2,
  "layout": "3LDK",
  "built_year_month": "2008-03",
  "management_fee": 12500,
  "repair_reserve": 9800,
  "land_rights": "所有権",
  "confidence": {"price": 0.99, "repair_reserve": 0.85},
  "needs_review": ["repair_reserve"]
}
```

### 方式B: 管理会社の自社サイトURL入力 → AI取得【Phase1.5で追加】

「URLを貼るだけ」のUXを、**管理会社自身が運営するページに限定**して提供する。

- 掲載規約で「入力するURLは自社が権利を有するページに限る」ことを保証させる
- ドメイン検証: 管理会社アカウント登録時に自社ドメインを申告 → 入力URLのドメインと照合。
  不一致（suumo.jp等の既知ポータルドメインを含む）は**システム側で拒否**する
- 取得はヘッドレスブラウザ（Playwright）+ Claude APIでHTML→構造化

### 方式C: 構造化フォーム + AI入力補助【フォールバック】

フリーテキスト（物件説明文のコピペ）から各項目をAIが自動入力補完。
概要書もURLもない場合の最終手段。常時提供しておく。

### 将来検討: 公式データ連携

- **不動産情報ライブラリAPI（国土交通省）**: 成約価格・地価情報。物件評価の裏付けデータとして合法的に利用可能（利用規約の範囲で）。評価エンジン側で採用推奨。
- **レインズ**: API公開はなく、IP制限・目的外利用禁止。自動連携は不可。管理会社が手元のレインズ登録内容を転記する運用は可。
- **各ポータルの正規提携・コンバートシステム（例: 不動産業者向け物件コンバート）**: 事業拡大時に正規ルートでの連携を検討。

## 技術構成

```
[管理会社UI]
  ├ 概要書アップロード ──→ Supabase Storage
  ├ 自社URL入力 ──────→ ドメイン検証 → Playwright取得
  └ フォーム入力
              ↓
[抽出パイプライン (Edge Function / Queue)]
  Claude API: 構造化抽出（JSONスキーマ強制 + 信頼度）
              ↓
[確認画面] 抽出結果を人間が確認・修正（needs_reviewをハイライト）
              ↓
[AI評価] → [社内審査] → 掲載
```

- 抽出は非同期ジョブにする（アップロード→「解析中」表示→完了通知）。
- **全項目に `source`（extracted / manual / verified）を持たせ、人間確認済みかを追跡**する。
  宅建業法の広告規制上、掲載情報の正確性の最終責任は運営にあるため、
  「AI抽出のまま未確認で公開」を仕組み上不可能にする（公開条件 = 全必須項目 verified）。
